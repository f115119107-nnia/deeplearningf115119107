# 交付工作項目

- [x] **Shopify 商品目錄與商品示範資料**
  - 依使用者要求使用 Shopify 整合建立小七超商線上店面，並以 Shopify 商品目錄作為店面商品資訊來源。
  - 新 Shopify 開發商店在未指定商品時建立恰好 2 項示範商品，不新增其他商品；每項商品均須附有商品圖片。
  - 示範商品圖片、名稱、價格及庫存狀態不得冒充小七實際商品、售價或門市庫存；店面須清楚標示為教學示範資料。
  - 商品目錄在伺服器端以 Shopify Storefront API 讀取，提供商品瀏覽與詳情頁。

- [x] **Shopify 購物車及結帳**
  - 購物車可新增、移除及調整商品數量，並顯示由 Shopify 返回的購物車摘要與金額。
  - 使用 Shopify 官方 Hydrogen CartProvider／forms／request parser 及伺服器端 Shopify Storefront Cart API；因管理 token 未提供本案不需要的 selling-plan scope，伺服器 route 只查必要欄位；不可用自製假結帳取代 Shopify。
  - 結帳按鈕導向 Shopify 託管結帳；Preview iframe 的購物車 cookie 設定支援 HTTPS 跨站情境，並保留 CSRF／origin 保護。

- [x] **AI 文字客服 Agent 與對話畫面**
  - 提供客人可使用的聊天畫面，客人與 Agent 訊息以左右對話氣泡呈現。
  - 客人的每個問題都先交給伺服器端 Agent，由 Agent 決定呼叫哪一個工具；店務回答必須使用工具取得的資料或程式計算，不可依模型記憶直接回答。
  - API 金鑰、Agent 迴圈、工具和 SQLite 資料庫都放在伺服器端；前端只傳送客人訊息並顯示回覆與安全的工具軌跡，不得將 API 金鑰放入前端／App 程式碼。
  - 至少 4 個工具，涵蓋資料查詢、紀錄查詢、程式計算及轉接真人客服；對話畫面展示工具選擇、執行狀態及可安全公開的結果摘要。
  - 若示範環境沒有連接真實人工客服排班，轉接結果須誠實揭露並提供官方聯絡方式，不得宣稱已完成即時轉接。

- [x] **CSV 匯入 SQLite 客服知識資料**
  - 客服知識使用 CSV 建立並匯入伺服器端 SQLite；至少包含 8 個客服知識主題、至少 15 筆知識資料紀錄；獨立的紀錄表至少包含 15 筆明確標記為虛構／匿名的示範紀錄。
  - 每筆知識須保留主題、問題、回答、來源／來源類型及示範資料標記；官方政策不得與本示範店自行設定混為一談。
  - 至少提供客服知識查詢工具、匿名示範紀錄查詢工具、示範購物車程式計算工具及真人客服轉接工具。
  - 未命中資料時應表示查無資料或交由真人，不可由模型補造政策、商品庫存或訂單狀態。

- [x] **問題與工具選擇測試**
  - 完成至少 10 題不同類型問題與工具選擇測試，涵蓋 FAQ 查詢、示範紀錄、計算、人工轉接，以及資料庫未命中／未知事項。
  - 驗證每題先由 Agent 選工具、工具路由符合問題類型、答案只根據工具結果、錯誤時不偽稱已查得資料。
  - 所有測試資料均須為匿名示範資料，不使用真實顧客個資或真實 Shopify 訂單。

- [x] **Windows 本機示範模式（不需 Shopify 或 Manus 憑證）**
  - 使用者已選擇本機示範模式；原 Shopify 雲端店面與 Shopify hosted checkout 保持不變。
  - 本機模式必須在 Windows 上以 Node.js 直接啟動，不需安裝 React Router 專案依賴或 Manus/Shopify API 金鑰，並可從瀏覽器顯示本站課堂示範商品與客服介面。
  - 原兩項示範商品名稱與價格須保留在本機至少 15 筆商品資料中，且至少 15 筆匿名示範客服紀錄須從 CSV seeded SQLite 提供；中文 FAQ 搜尋在系統 SQLite 未編譯 FTS5 時仍須可用。
  - 客人可在瀏覽器本機購物袋加購、變更數量及移除；不可冒稱這是真正 Shopify cart／訂單，不可收取付款；結帳按鈕必須清楚揭露此模式不建立真實訂單或付款。
  - 每個客服問題由伺服器端 Ollama Agent 先選一項工具，至少提供 FAQ 查詢、匿名示範紀錄、程式購物籃計算、真人官方聯絡資訊四工具；答案只能由 SQLite／程式計算的工具輸出組成，不得模型憑記憶作答，並顯示安全工具軌跡。
  - Ollama 未啟動或無合適模型時，介面須顯示明確可恢復的錯誤；不得直接暴露 Ollama API 給瀏覽器或把金鑰寫入前端。HTTP server 預設僅聽 localhost。
  - 提供給搬移電腦使用的繁體中文操作說明：Node 啟動方式、Ollama 安裝／模型下載、localhost 網址及本機購物袋／無付款限制。

- [x] **期中版 RAG 與五段 System Prompt**
  - 延伸 Unit G 客服作業必須新增 RAG；RAG 用於檢索長篇自由文字服務規則，表格型商品、示範記錄及預留資料仍由工具查詢，不能拿 RAG 取代可變資料工具。
  - App 必須有清楚的客服對象／目的與至少三條操作規則；System Prompt 必須包含「角色與目標、範圍、互動規則、拒答與特殊情況、開場白」五部分。
  - App 必須有對話畫面、開場白和範例問題，並在同一聊天工作階段記住近期對話供後續追問；記憶只作上下文，不是答案證據。
  - 超出小七客服範圍時用固定句拒答；SQLite/RAG 找不到答案時用固定句說明查無資料並提供安全的官方管道；RAG 模型只能選擇檢索文件中的逐字句子，伺服器須核對 SQLite 原文，無效／捏造引文須丟棄，不得捏造答案或洩漏 System Prompt。
  - 只使用明確標示的虛構示範資料及附官方來源連結的公開 7-ELEVEN 資訊，不使用真實顧客姓名、電話、學生 ID 或真實訂單。

- [x] **確認後才寫入的本機示範工具**
  - Agent 可準備虛構的示範商品預留，但第一步只產生待確認摘要，不得寫入預留資料表。
  - 必須先向客人明確顯示商品、數量、示範價格與取消／確認選項；只有客人針對目前 session 的待確認項目明確同意後，伺服器才將匿名示範記錄新增到 SQLite。
  - 拒絕、超時、沒有待確認項目、非明確同意或重送確認不得新增資料或重複寫入；不得收集真實姓名／電話，也不得宣稱預留了真實 7-ELEVEN 門市庫存。
  - 成功確認後回傳示範預留編號並讓使用者能查到本 session 的已保存資料；RAG 僅檢索規則，不負責寫入可變資料。

- [x] **中英雙語、彈性商品名稱與範圍安全**
  - 商品資料須有繁體中文名稱欄和英文名稱欄，並保存適合的別名／關鍵字；目前問題由程式判定回覆語言，中文問題回繁中、英文問題回英文。
  - 商品計算與預留工具須能接受非完全相同的商品名稱；只接受唯一且達配對門檻的商品，歧義或低信心配對要澄清或安全拒答，不得任意挑選。
  - 以新對話測試正常客服、查無資料、超出範圍、要求忽略規則、索取 System Prompt、角色扮演越權及確認／取消寫入；任何測試若違反規則都要修正並重測。
